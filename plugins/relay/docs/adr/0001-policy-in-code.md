# relay 정책의 정본은 코드, orca 사용법의 정본은 Orca 가이드

진행 세션의 판단은 대부분 조건 분기(심각도 분기, 라운드 판정, 무응답 판정, 기동 응답 해석)인데, 이를 SKILL.md의 표로 두면 Sonnet이 매번 산문에서 재계산하고 표와 실제 동작이 조용히 어긋난다(리뷰어 `--uncommitted` 드리프트가 실례). 그래서 relay 정책은 `relay_cli.py`의 결정기·검사기와 그 테스트를 정본으로 삼고 SKILL.md에는 실행 방법과 분기의 이유만 남긴다. 반대로 스크립트는 orca 명령을 조립하지 않고 결정(`{"action": ...}`)만 돌려준다 — orca 플래그는 릴리스마다 바뀌고 Orca가 정본 가이드를 직접 서빙하므로, 명령 조립은 SKILL.md가 정본을 따라 한다.

## Considered Options

- **표와 스크립트 병행 + 정합성 테스트**: 사람이 읽기 쉽지만 규칙을 두 곳에서 고쳐야 한다. 기각.
- **스크립트가 실행할 orca argv까지 반환**: 진행자가 단순해지지만 orca 플래그가 코드에 박혀 "캐시된 복사본에서 플래그를 추측하지 말라"는 Orca 정본 원칙과 충돌한다. 기각.

## Consequences

- 정책을 바꾸려면 SKILL.md가 아니라 `relaylib/`과 `tests/`를 고친다.
- SKILL.md에 남은 산문(행동→orca 명령 대응, 금지 행동, 발동 조건)은 단위 테스트가 닿지 않으므로 `evals/`가 덮는다.
