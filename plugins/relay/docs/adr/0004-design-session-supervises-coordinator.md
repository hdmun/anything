# 설계 세션이 진행자를 Orca 워커로 감독한다

지금까지는 사람이 설계 세션(Opus)과 진행 세션(Sonnet)을 따로 열고 Run ID 를 손으로 옮겼다. 에스컬레이션은 decision gate 를 만들고 세션을 끝낸 뒤 사람이 Opus 세션을 다시 열어 `gate-list`·`gate-resolve` 로 닫는 왕복이었고, 정착한 Task 에 게이트가 걸리는지는 끝내 검증되지 않았다. 그래서 **relay 를 호출한 세션이 설계 세션**이 되어 spec·Run·Task 를 만든 뒤, ready 태스크마다 **진행자 워커**를 `worker-start --agent claude` 로 띄워 감독한다(순차). 진행자는 구현자·리뷰어를 자기 하위 워커로 띄운다. 진행자가 혼자 판단할 수 없는 것(SPEC_VIOLATION, 반복 지적, 라운드 한도, 사람이 필요한 상황)은 모두 `ask` 로 설계 세션에 묻고, 설계 세션이 직접 답하거나 사람에게 넘긴 뒤 답한다. 세션 판정은 Orca 의 역할 판정과 같다 — Orca preamble 이 있으면 진행자, 없으면 설계 세션.

## Considered Options

- **설계만 하고 끝내기(구조 유지, Opus 요구만 제거)**: 세션을 두 번 여는 왕복과 미검증 decision gate 가 남는다. 기각.
- **한 세션이 설계와 진행을 모두**: 잦고 긴 진행 구간을 싼 모델에 두는 비용 근거를 잃고, 태스크마다 컨텍스트가 누적된다. 기각.
- **에스컬레이션을 decision gate 로 유지**: 게이트는 세션 종료를 전제로 한 설계였다. 진행자는 답을 기다리는 동안 워크트리·하위 워커 문맥을 유지하는 편이 낫고, 그 용도로 Orca 가 주는 것이 블로킹 `ask` 다. 기각.

## Consequences

- 설계 세션은 Run 이 끝날 때까지 떠 있다. 컨텍스트가 커지면 새 세션을 열어 `run-use` 로 이어 간다.
- "태스크마다 세션 폐기"는 "태스크마다 진행자 워커를 새로 띄우고 해제"로 바뀐다.
- 진행자의 `worker_done` 뒤 설계 세션은 게이트를 다시 돌리지 않고 `commit-guard`·리뷰 리포트 존재·`git log <base>..HEAD` 만 확인한다. 게이트 재검증은 진행자의 몫이다.
- 사람 호출은 모두 설계 세션을 거친다. `ask` 는 한 번에 최대 30분이고, 넘으면 같은 메시지 ID 로 이어 기다린다.
- 워커 중첩 깊이가 2(설계 → 진행자 → 구현자·리뷰어)가 된다. Orca 기본값은 1이라 진행자가 하위 워커를 띄우면 `nested_worker_depth_exceeded` 로 거부된다(2026-11-02 실측). 그래서 Orca 설정 "Nested worker depth"(Settings → Orchestration)를 2 이상으로 올리는 것이 relay 의 사전 조건이고, `doctor` 가 검사한다. 깊이 1을 지키려면 설계 세션이 진행 루프를 직접 돌아야 하는데, 태스크가 쌓일수록 Opus 컨텍스트가 커져 이 ADR 의 비용 근거를 잃는다.
