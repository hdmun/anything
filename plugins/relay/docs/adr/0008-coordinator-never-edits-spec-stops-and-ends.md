# 진행자는 spec 을 고치지 않고, 멈추면 끝나며, 재개는 다시 핸드오프한다

ADR 0005 로 설계 세션이 핸드오프 뒤 끝나면서, 예전 경로(설계 세션이 `spec을 고친다` 를 골라 워크트리 spec 에 설계자 주체 커밋을 남김)를 맡을 주체가 없어졌다. 그래서 **진행자 세션의 판정 서브에이전트는 spec 안에서 풀리는 것만 판정한다.** `spec_violation` 에서는 `구현을 고친다`·`지적을 기각한다`(근거는 PR 본문에)만 고르고, 구현자의 해석 `question` 은 spec 스냅숏과 코드로 답이 나올 때만 답한다. spec 이 틀렸다는 판정, spec 에 없는 새 결정, 「태스크를 쪼개야 한다」는 판정이 나오면 진행자는 이슈를 고치지 않고 **멈춤 보고**(구현 이슈 코멘트 + Orca 미읽음)를 한 뒤 **끝난다.** PR 은 열지 않고 브랜치·워크트리는 남긴다. 사람이 구현 이슈를 고친 뒤 같은 이슈로 `relay:handoff` 를 다시 실행하는 것이 **재개**다. 새 진행자는 성공으로 끝난 태스크(리뷰 `pass`, 또는 판정으로 성공 처리 — 표지는 ADR 0010)를 건너뛰고, 멈춘 태스크는 spec 스냅숏을 다시 커밋해 라운드를 처음부터 센다.

## Considered Options

- **문구만 고치는 수정은 진행자가 이슈를 고친다**: 「이 수정이 동작을 바꾸지 않는가」라는 판정이 하나 더 생겨 경계가 흐려진다. spec 을 고치는 것은 설계 결정이다. 기각.
- **판정 서브에이전트가 `spec을 고친다` 까지 고른다**: 설계를 진행자가 다시 하게 된다. 기각.
- **멈춘 뒤 진행자 세션이 살아서 사람의 답을 기다린다**: 한 줄 답으로 바로 이어 갈 수 있지만, 세션이 몇 시간에서 며칠 떠 있고(ADR 0005 의 컨텍스트 누적 재검토 조건을 키운다) 사람의 결정이 이슈 본문 밖의 두 번째 입력 경로로 들어온다. 기각.
- **진행자에 태스크 크기 감지기를 둔다**: 크기 문제는 `repeated_finding` 과 총 라운드 한도로 늦어도 리뷰 3회차에 드러난다. 규칙만 늘어난다. 기각.

## Consequences

- 「설계자 주체 커밋」은 사라진다. spec 스냅숏은 언제나 진행자가 커밋한다(처음 시작과 재개 때).
- 재개는 처음 시작과 같은 명령이다. 진행자는 시작할 때 브랜치에서 끝난 태스크를 알아봐야 한다.
- 사람이 「spec 이 맞다, 구현을 고쳐라」로 정해도 그 결정은 이슈 본문에 적어야 전달된다. 스냅숏은 본문만 담는다(ADR 0006).
- 멈춘 뒤 지도에 결정 티켓을 만들지, 닫힌 지도를 다시 열지, 이슈만 고칠지, 이슈를 닫을지는 사람이 정한다. relay 는 wayfinder 를 모른다.
- 판정 서브에이전트에 사람 대신 「spec 이 틀렸다」를 고를 권한은 없다. `review.md` 의 「SPEC_VIOLATION 은 진행자가 판단하지 않는다」는 「spec 안에서는 판정하고, spec 이 틀렸으면 멈춘다」로 바뀐다.
