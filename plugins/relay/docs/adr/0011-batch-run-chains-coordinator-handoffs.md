# 일괄 진행은 진행자 세션끼리 연쇄 handoff 로 잇고, 진행자 세션은 마지막에 자기 이슈 워크트리를 지운다

일괄 진행은 진행 목록의 구현 이슈를 차례로 머지까지 옮긴다. 진행자 세션 하나는 구현 이슈 하나만 돌고 끝난다(ADR 0005·0007). 그래서 다음 구현 이슈의 진행자 세션을 띄울 주체가 필요했다. Orca 1.4.253 에는 「세션이 끝나면 다음 세션을 띄운다」는 내장 트리거가 없다. **머지에 성공한 진행자 세션이 마지막 단계에서 다음 구현 이슈를 handoff 한다(머신 점검 + 기동 전 검사 + `worktree create --no-parent --agent claude`).** 다음 이슈는 기동 줄로 넘겨받은 진행 목록에서 아직 열린 첫 이슈다. 그다음 진행자 세션은 `orca worktree rm --worktree current --delete-branch` 로 자기 이슈 워크트리를 지운다. 이것이 마지막 행동이다. 멈춤 보고로 끝난 진행자 세션은 handoff 하지 않고 워크트리도 지우지 않는다.

## Considered Options

- **오래 사는 감독 세션**이 진행자 세션을 워커로 띄우고 `worker_done` 으로 깨어난다: 워크트리 정리·알림·멈춤 처리를 한 곳에 둘 수 있다. 중첩 깊이 2 는 이 PC 설정(2)으로 된다. 하지만 진행자 세션이 최상위 코디네이터에서 워커로 바뀌고, ADR 0005 가 기각한 「중첩 워커 위의 relay」로 돌아간다. 기각.
- **Orca 플러그인**(`agent.status.changed` → `agent.launch`): 사람 승인이 필요하고 model·effort 를 줄 수 없다. 기각.
- **Orca automations**: 트리거가 일정뿐이라 폴링이 된다(ADR 0009). 기각.
- **다음 진행자 세션이 앞 이슈 워크트리를 지운다**: 지운 결과를 볼 수 있다. 하지만 마지막 구현 이슈의 워크트리가 남는다. 구현 이슈가 하나뿐인 진행 목록(지금까지의 모든 경우)에서는 한 번도 지우지 않는다. 기각.

ADR 0005 가 기각한 「연쇄 핸드오프」는 **태스크 사이**의 Run 승계 문제였다. 여기서는 구현 이슈마다 Run 이 따로라 승계가 없다.

## Consequences

- 성공한 진행자 세션의 끝 순서: 머지와 머지 뒤 확인 → 사람에게 알림 → (다음 이슈가 있으면) handoff → 자기 워크트리 삭제. 알림과 보고는 삭제 전에 끝낸다. 삭제를 부른 세션은 Orca 가 먼저 끄므로 결과를 받지 못한다(2026-11-09 셸 터미널로 실측: 디렉터리·git worktree 항목·로컬 브랜치·Orca 항목이 8초 안에 지워짐).
- `--force` 를 쓰지 않는다. 커밋하지 않은 파일이 있으면 Orca 가 세션을 끄기 전에 거부한다. 이때 진행자 세션은 워크트리를 남기고 이유를 보고한다. Orca 가 머지를 증명하지 못한 브랜치는 남는다.
- 다음 handoff 가 실패하면 다음 구현 이슈에 멈춤 보고를 남기고, 자기 워크트리는 지운다(자기 이슈는 머지됐다).
- 진행 목록은 시작 때 고정해 기동 줄로 넘긴다. 시작한 뒤에 blocking 으로 이어진 이슈는 들지 않는다. 시작 때 사람이 있는 동안 모든 이슈를 검사하기 때문이다.
- 진행자 세션이 멈추면 연쇄가 끊긴다. 진행 목록의 나머지를 어떻게 하는지는 따로 정한다.
- **재검토 조건**: Claude Code 세션에서 자기 워크트리 삭제가 실패하면, 또는 Orca 가 세션 종료 트리거를 내주면 다시 본다.
