# relay

설계자·진행자·구현자·리뷰어 네 역할로 구현 이슈 하나를 spec부터 머지 직전까지 옮기는 파이프라인의 용어집이다.

## Language

### 세션과 워커

**설계 세션**:
사람과 함께 무엇을 만들지 정해 구현 이슈를 쓰고, 그 이슈를 **진행자 세션**에 핸드오프한 뒤 끝나는 세션. Run 을 소유하지 않고 감독하지 않으며, relay 스킬을 읽지 않는다.
_Avoid_: relay 를 호출한 세션, Opus 세션 (모델은 설정이 정한다), 코디네이터

**진행자 세션**:
설계 세션의 핸드오프로 떠서 구현 이슈 하나의 Run 을 소유하는 최상위 코디네이터. 이슈의 **태스크**를 차례로 돌며 구현자·리뷰어를 워커로 띄워 감독하고, 게이트 재검증·리뷰 분기·판정·PR 생성까지 한다. PR 은 구현 이슈마다 하나다. 혼자 풀 수 없으면 멈추고 사람에게 보고한다.
_Avoid_: 진행자 워커 (dispatch 된 워커가 아니다), 진행 세션 (사람이 따로 여는 세션이라는 옛 뜻이 남아 있다)

**판정 서브에이전트**:
진행자 세션이 SPEC_VIOLATION·반복 지적·구현자의 spec 해석 질문을 맡기는 일회성 서브에이전트. 진행 루프보다 높은 effort 로 돌고, spec 스냅숏과 브랜치를 읽기만 하며, 판정 하나만 진행자에게 돌려준다. spec 안에서 풀리지 않으면 멈춤을 고른다. 진행자는 spec 을 스스로 해석하지 않는다.
_Avoid_: 리뷰어 (리뷰 리포트를 쓰는 역할과 다르다), 설계자

**판정 기록**:
SPEC_VIOLATION·반복 지적에 대한 판정 하나를 이슈 워크트리에 커밋으로 남긴 것. 무엇을 골랐는지와 그 근거를 담고, 성공 처리 판정이면 그 태스크가 끝났다는 표지도 된다. 기각 근거는 여기서 PR 본문으로 옮겨진다. spec 해석 질문의 답은 판정 기록을 남기지 않는다.
_Avoid_: 판정 로그, 결정 기록 (ADR 과 헷갈린다)

**멈춤 보고**:
진행자 세션이 혼자 풀 수 없는 상황(spec 이 틀렸다는 판정, spec 에 없는 새 결정, 사람을 부르는 한도·실패)에서 구현 이슈 코멘트와 Orca 미읽음으로 남기는 보고. 무엇을 정해야 하는지를 한 줄로 적고, 진행자 세션은 그 뒤 끝난다. 다음 결정을 어디서 할지는 사람이 정한다.
_Avoid_: 에스컬레이션 (옛 `ask` 중계를 가리킨다), 사람 호출

**재개**:
멈춤 보고 뒤 사람이 구현 이슈를 고치고 같은 이슈로 진행자 세션을 다시 띄우는 일. 같은 **이슈 워크트리**에서 이어 가며, 성공으로 끝난 태스크(리뷰 통과든 판정으로 성공 처리됐든)는 건너뛰고, 멈춘 태스크는 spec 스냅숏을 다시 떠서 라운드를 처음부터 센다. 사람의 결정은 이슈 본문으로만 전해진다. **일괄 진행**의 재개는 일괄 진행 시작 명령을 다시 실행하는 일이다. 진행 목록을 그때 새로 만든다. `relay:handoff` 로 재개하면 그 구현 이슈 하나만 PR 까지 간다.
_Avoid_: 이어하기, resume (Orca `ask` 의 resume 과 다르다)

**일괄 진행**:
사람이 명령 한 번으로 구현 이슈를 맡기면, 그 이슈의 **진행 목록**에 든 구현 이슈를 차례로 PR 머지와 이슈 닫힘까지 사람 없이 옮기는 진행. 구현 이슈마다 PR 하나를 열고 머지하며, 머지한 진행자 세션이 다음 구현 이슈의 진행자 세션을 띄운다. 사람만 할 수 있는 단계(관리자 권한, 실제 기기 시험 등)는 머지 뒤 사람이 할 일로 남고, 그런 단계가 머지 전에 필요한 구현 이슈가 진행 목록에 하나라도 있으면 시작하지 않는다. 구현 이슈 하나가 멈추면 진행 목록의 나머지도 시작하지 않는다.
_Avoid_: 무인 진행 (옛 이름), 완전 자동, auto mode, 자동 머지 (GitHub 의 auto-merge 기능과 헷갈린다)

**진행 목록**:
일괄 진행을 시작할 때 고정하는, 순서가 있는 구현 이슈 목록. 맡긴 구현 이슈와 blocking 으로 이어진 열린 구현 이슈를 모두 담고(닫힌 이슈를 거쳐 이어져도 든다), 막는 이슈가 막히는 이슈보다 앞에 온다. 시작한 뒤에 이어진 이슈는 들지 않는다. **재개** 때는 새로 만든다.
_Avoid_: 묶음 (하위 이슈를 가진 구현 이슈를 뜻한다), 계획 (wayfinder 지도·설계와 헷갈린다), 이슈 사슬

**머지 조건**:
일괄 진행이 사람의 확인 없이 PR 을 머지해도 되는 조건 모음. 하나라도 어긋나면 머지하지 않고 PR 을 연 채 멈춤 보고를 남긴다. 조건은 기계로 판정할 수 있는 것만 둔다(게이트 종료코드, 리뷰·판정 기록, 이슈 본문). 머지를 막지 않고 PR 본문에 기록만 남기는 것(기각한 지적, 남은 MINOR 등)은 머지 조건이 아니다.
_Avoid_: 자동 머지 규칙, 머지 정책

**유출 검사**:
진행자 세션이 무언가를 원격에 내보내기 직전(이슈 브랜치 푸시, PR 본문, 이슈 코멘트)에 토큰·웹훅 URL·실제 IP·PC 이름이 들었는지 기계로 보는 검사. 저장소의 공개 여부와 상관없이, 일괄 진행이든 구현 이슈 하나만 맡긴 진행이든 모두 돈다. 걸리면 내보내지 않고 멈춤 보고를 남기며, 보고에는 걸린 값을 적지 않는다. 머지 조건과 달리 PR 을 열기 전에 막는다.
_Avoid_: secret scanning (GitHub 기능 이름), 비밀 검사 (비밀이 아닌 IP·PC 이름도 잡는다)

**이슈 워크트리**:
구현 이슈 하나에 하나뿐인 작업 공간과 그 브랜치. `relay:handoff` 가 진행자 세션과 함께 만들고, 진행자 세션과 구현자·리뷰어 워커가 모두 이 안에서 일한다. 이슈의 태스크가 차례로 같은 브랜치에 쌓이고, 재개도 여기서 한다.
_Avoid_: 태스크 워크트리 (태스크마다 워크트리를 만들던 옛 구조)

### 에이전트 CLI

**모델 계열**:
역할에 배정하는 모델의 지정 단위(예: Opus, Sonnet, agy 기본 모델). 플러그인의 기본값은 특정 버전이 아니며, 실제로 쓰인 버전은 사후 기록으로만 남는다.
_Avoid_: 모델 버전, 모델 ID

**모델 설정**:
사용자가 역할별 model·effort 를 정하는 파일(`~/.relay/models.json`, `<저장소>/.ai/relay-models.json`). 둘을 필드 단위로 겹치고, 비어 있는 필드는 기본값으로 돌아가되, 리뷰어 model 만은 기본값이 없어 비어 있으면 기동하지 않는다(codex 의 config.toml model 로 되돌아가지 않는다). 버전은 이 파일에만 적힌다.
_Avoid_: 모델 매핑, 역할 설정 (역할 파일 `.ai/roles/` 과 헷갈린다)

**검증된 버전**:
실제 기동과 전달 확인을 통과했다고 사람이 등록한 에이전트 CLI 버전. 목록 밖의 버전은 작동하더라도 미검증으로 본다.
_Avoid_: 지원 버전, 호환 버전

**예열**:
워커를 띄우기 전에 Task 밖에서 에이전트 CLI의 자동 업데이트를 끝내 두는 일. 업데이트를 막는 대신 버전 변화를 Task 예산 밖에서 흡수한다.
_Avoid_: 워밍업 기동, 사전 실행

**머신 점검**:
에이전트 CLI·설정 파일·Orca 스킬·플러그인 사본처럼 이 머신의 상태만 보는 검사(`doctor`). 어떤 이슈를 돌릴지와 무관하다. handoff 전, 진행자 세션 시작 때, 사람이 원할 때 돈다.
_Avoid_: 사전 점검, 헬스 체크

### spec

**구현 이슈**:
설계 세션이 트래커(저장소의 트래커 설정을 따름)에 쓰는 이슈. 진행자 세션이 받는 입력이다. 하위 이슈가 없으면 이슈 자체가 **태스크** 하나이고 그 spec 의 **정본**이다. 하위 이슈가 있으면 Run 의 목표와 하위 이슈 목록을 담는 묶음이고, spec 의 정본은 하위 이슈 각각이다.
_Avoid_: spec 파일, T-NNN (옛 정본), 티켓 (wayfinder 의 결정 티켓과 헷갈린다)

**태스크**:
진행자 세션이 구현 라운드와 리뷰 라운드로 돌리는 relay 의 작업 단위. 구현 이슈의 하위 이슈 하나이고, 하위 이슈가 없으면 구현 이슈 자체다. 나누는 것은 설계 세션의 몫이다.
_Avoid_: Orca Task (진행자가 워커를 띄울 때 생기는 Orca 의 Task 와 다르다), T-NNN (옛 ID 체계), 티켓

**spec 스냅숏**:
진행자 세션이 태스크를 시작할 때 그 태스크의 이슈 본문을 워크트리 `.ai/specs/` 에 커밋한 고정 사본. 묶음인 구현 이슈는 뜨지 않는다. 머리말에 이슈 URL 과 `updatedAt` 을 적는다. 리뷰어는 이것을 읽고, **재개** 때만 다시 뜬다. 진행자 세션은 이슈를 고치지 않는다.
_Avoid_: spec 원본, 명세 파일

**기동 전 검사**:
`relay:handoff` 가 진행자 세션을 띄우기 전에 구현 이슈 하나를 보는 입력 검사: 태스크 수, 템플릿 필수 절, 작성자 권한. 머신 점검과 함께 돌고, 둘 중 하나라도 실패하면 진행자 세션을 띄우지 않는다.
_Avoid_: 이슈 doctor, 사전 검증

### 시도와 라운드

**기동 실패**:
워커가 태스크 프롬프트를 받기 전에 실패한 것. Orca가 실패로 보고한 경우와 **전달 확인**에 실패한 경우를 모두 포함한다. 환경 문제이므로 라운드로 세지 않는다.
_Avoid_: 라운드, 재시도 라운드

**전달 확인**:
기동 직후, 워커가 태스크 프롬프트를 실제로 받았다는 양성 증거를 확인하는 일. Orca의 "입력 수락"은 전달의 증거가 아니다.
_Avoid_: 기동 확인, 준비 확인

**구현 라운드**:
게이트를 통과해 커밋으로 남은 구현 한 번.
_Avoid_: 구현 시도, 회차

**리뷰 라운드**:
리뷰어가 낸 리뷰 리포트 하나.
_Avoid_: 리뷰 회차, 리뷰 시도

**총 라운드**:
한 태스크의 구현 라운드와 리뷰 라운드를 합한 수. 기동 실패는 포함하지 않는다.
_Avoid_: 전체 시도 수

### 규칙의 출처

**Orca 가이드**:
그 시점의 Orca 바이너리가 자기 버전에 맞춰 내주는 사용법 전체. orchestration 가이드(Run·Task·Dispatch·워커 감독)와 orca-cli 가이드(워크트리·터미널), 그리고 각자의 references 를 포함한다. 명령·플래그 사용법은 이것이 판정하며, relay 문서와 어긋나면 relay 문서를 고친다.
_Avoid_: 정본 (단독으로 쓸 때), orca 문서

**Orca 스킬**:
`orchestration`·`orca-cli` 라는 이름의 껍데기 스킬. 쓸 실행 파일을 고르고 **Orca 가이드**를 불러오는 통로일 뿐, 그 자체는 사용법의 정본이 아니다. 코디네이터와 워커가 같은 통로로 가이드를 읽는다.
_Avoid_: 오케스트레이션 스킬 (orchestration 하나만 가리키는 것처럼 읽힌다), Orca 가이드 (통로와 내용을 섞는다)

**정본**:
어떤 규칙 하나를 판정하는 단 하나의 코드나 파일. 항상 무엇의 정본인지 함께 적는다(예: 라운드 한도의 정본, 역할 파일의 정본). 같은 규칙을 다른 문서가 다시 적으면 그 문서는 사본이다.
_Avoid_: 원본, 기준 문서
