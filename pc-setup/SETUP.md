# 셋업 (SETUP.md)

이 파일은 **셋업**을 진행하는 에이전트(Claude Code·agy·Codex)가 읽는 지시문이다. 사람이 `pc-setup` 폴더에서 에이전트를 띄우고 "SETUP.md 를 읽고 셋업해"라고 하면 시작한다. 새 PC 에서도, 이미 셋업한 PC 에서도 시작 줄은 같다. 상태만 보고 싶을 때도 같은 시작 줄로 시작하고, **계획** 단계에서 "중단"이라고 답한다.

어느 권한 모드로 열어도 된다. 자동 승인 모드가 아니면 에이전트 도구가 명령마다 사람에게 묻는다.

용어는 [CONTEXT.md](CONTEXT.md) 를 따른다. 이 문서에서 **저장소 폴더**는 이 파일이 든 `pc-setup` 폴더의 부모 폴더(git 저장소의 맨 위 폴더)다.

## 선언

| 순서 | 선언 | 이 순서인 이유 |
|---|---|---|
| 1 | [windows-settings.md](windows-settings.md) | 개발자 모드처럼 뒤 단계가 기대는 Windows 설정을 먼저 맞춘다 |
| 2 | [apps.md](apps.md) | 설정 파일과 저장소 도구가 앱에 의존한다 |
| 3 | [config-files.md](config-files.md) | 설정 파일의 원래 자리는 앱이 설치된 뒤에야 생긴다 |
| 4 | [repo-tools.md](repo-tools.md) | 저장소 도구는 앱(pwsh·git 등)에 의존한다 |

각 선언 파일 맨 위의 「기본 규칙」이 그 분류의 확인 기준이다. 표 아래에 절이 있는 항목은 그 절의 기준이 기본 규칙보다 앞선다.

## 지킬 규칙

1. **계획 승인 전에는 확인 명령만 실행한다.** PC 상태를 바꾸는 명령(설치·설정 변경·파일 연결)은 사람이 계획을 승인한 뒤에만 실행한다.
2. **선언에 있는 항목만 바꾼다.** 선언에 없는 앱을 지우거나, 선언에 없는 설정을 바꾸지 않는다. 선언에 없는 것은 보지도 알리지도 않는다.
3. **저장소 파일을 고치지 않는다.** 셋업은 PC 만 바꾼다. 선언 쪽 문제(확인 기준이 틀림 등)를 찾으면 끝 요약의 `할 일:` 에 "선언 수정 제안: …"으로만 남긴다.
4. **PATH 와 설정 파일은 반드시 `tools/` 스크립트로 맞춘다.**
   - 사용자 PATH: `pwsh -NoProfile -File tools/add-user-path.ps1 -Entry <경로> [-Prepend] [-Check]`
   - 설정 파일: `pwsh -NoProfile -File tools/link-config.ps1 -Source <정본> -Target <원래 자리> -Mode Link|GitInclude [-Check]`
   - `setx`, PATH 를 직접 쓰는 명령, 링크를 직접 만드는 명령(`New-Item -ItemType SymbolicLink`, `mklink` 등)은 쓰지 않는다.
   - 두 스크립트는 한 줄을 출력한다: `그대로` / `다름: …`(`-Check` 일 때만) / `바꿈: …` / `실패: …`. `실패`일 때만 종료 코드가 0 이 아니다. 앱 설치 프로그램이 PATH 를 넣지 않아 PATH 만 맞추는 경우도 이 스크립트를 쓴다.
5. **방법은 실행할 때 공식 문서에서 찾는다.** 선언에는 설치 방법·URL·레지스트리 값이 없다.
   - 공식 문서의 범위: 앱 제작사의 도메인, 제작사의 공식 GitHub 저장소, 원천 자체(winget·scoop 매니페스트, npm 레지스트리, PowerShell Gallery 등). 블로그·Q&A·비공식 미러는 쓰지 않는다.
   - 이 범위에서 방법을 확실히 찾지 못하면, 사람에게 묻지 않고 `실패: 방법을 찾지 못함 (<찾아본 곳>)`으로 기록한 뒤 다음 항목으로 넘어간다. 추측으로 설치하지 않는다.
6. **이미 설치된 앱의 버전을 올리지 않는다.** 업그레이드는 셋업 밖에서 한다.
7. **재부팅하지 않는다.** 재부팅해야 재확인을 통과하는 항목은 `할 일: 재부팅 뒤 셋업을 다시 실행`으로 기록한다.
8. **승격은 승격 단계에서만 한다.** 승격 표시가 없는 항목이 권한 부족으로 실패하면 스스로 승격하지 않고 `실패: 권한 부족 (승격 칸 확인 필요)`로 기록한다.
9. **PATH 는 레지스트리에서 다시 읽는다.** 에이전트의 셸은 시작할 때 물려받은 PATH 를 쓰므로, 설치한 명령이 PATH 에서 실행되는지 볼 때는 레지스트리의 시스템 PATH 와 사용자 PATH 를 다시 읽은 값으로 본다.

## 결과 말

| 결과 말 | 뜻 |
|---|---|
| `그대로` | 확인 기준을 통과했다. 아무것도 바꾸지 않았다 |
| `바꿈` | 기준과 달라서 맞췄고, 같은 기준으로 다시 확인해 통과했다 |
| `할 일` | 사람이 처리해야 할 일이 있다(재부팅, 사람만 할 수 있는 설정 등) |
| `실패` | 맞추지 못했거나, 맞춘 뒤 재확인을 통과하지 못했거나, 확인하지 못했다 |

사람이 "Docker 는 빼고"처럼 말로 뺀 항목은 결과 말을 붙이지 않고 요약에도 넣지 않는다.

## 절차

### 1. 시작 검사

- 관리자 권한 창에서 실행 중이면 "셋업은 일반 권한 창에서 실행한다"를 출력하고 멈춘다.
- 선언 파일 4개를 읽는다. 하나라도 읽지 못하면 그 파일 이름을 알리고 멈춘다.
- 실행 전체를 멈추는 경우는 이 두 가지뿐이다. 그 밖의 문제는 항목의 `실패`로 기록하고 계속한다.

### 2. 확인 (일반 권한, 읽기만)

고정 항목부터, 그다음 선언을 위 순서대로 확인한다. 항목마다 다음 셋 가운데 하나로 나눈다.

- **그대로**: 기준을 통과했다.
- **맞출 항목**: 기준과 다르다. 무엇이 다른지 짧게 적는다.
- **확인 못 함**: 일반 권한으로 확인하지 못했다. 이유를 적는다. 이 항목은 맞추지 않으며, 끝 요약에 `실패: 확인 못 함 (<이유>)`로 기록한다. 예외는 승격 **저장소 도구**다([repo-tools.md](repo-tools.md)).

**고정 항목 `ANYTHING_REPO`**: 사용자 환경 변수 `ANYTHING_REPO` 가 저장소 폴더의 절대 경로와 같으면 `그대로`다. 다르거나 없으면 맞출 항목이다. 스크립트 없이 에이전트가 사용자 환경 변수로 직접 맞추고, 다시 읽어 확인한다(PATH 가 아니므로 `tools/` 스크립트를 쓰지 않는다). 승격 항목이 아니다.

맞출 항목마다 원천과 방법을 공식 문서에서 찾아 둔다. 이 단계에서도 찾기와 읽기만 한다.

### 3. 계획

확인이 끝나면 **계획**을 대화에 보여 주고 사람의 답을 기다린다. 계획에는 다음을 넣는다.

1. **맞출 항목**: 분류별로, 항목마다 무엇이 다른지·원천·참고한 공식 문서 URL.
2. **승격 단계**: 승격 항목 목록과 승격 단계 스크립트의 전체 내용. 승격 저장소 도구는 "<도구>: 승격 안에서 확인하고 맞춤 (UAC 1회 필요)" 한 줄로 보여 준다. 승격 단계가 없으면 "UAC 를 묻지 않는다"고 적는다.
3. **확인 못 함**: 맞추지 않을 항목과 그 이유.
4. 그대로인 항목은 분류별 개수만 적는다.

사람의 답에 따라 진행한다.

- "진행": 끝까지 사람에게 다시 묻지 않고 실행한다. 승격 단계 스크립트는 계획에서 내용을 보여 준 것으로 승인이 끝난다(UAC 창이 두 번째 확인이다).
- "<항목> 은 빼고 진행"처럼 고친 승인: 뺀 항목은 말로 뺀 항목으로 다루고 나머지를 진행한다.
- "중단": 아무것도 바꾸지 않는다. 끝 요약을 내지 않고 "아무것도 바꾸지 않았습니다" 한 줄로 끝낸다.

승인 뒤 계획과 다르게 할 수 있는 일은 하나뿐이다. 같은 항목 안에서 공식 문서 범위의 다른 방법으로 바꾸는 것이고, 그렇게 하면 끝 요약의 그 항목 줄에 "계획과 다른 방법"이라고 적는다. 계획에 없던 항목을 더하거나 선언 밖을 바꾸는 일은 실행하지 않고 `실패`로 기록하며, 다시 묻지 않는다.

### 4. 승격 단계

맞출 승격 항목이나 승격 저장소 도구가 있을 때만 한다. 없으면 UAC 를 묻지 않고 5단계로 간다.

1. 승격 항목을 모두 담은 스크립트 하나를 `$env:TEMP` 에 새로 만든다. 계획에서 보여 준 내용과 같아야 한다. 저장소에 고정된 스크립트로 두지 않는다.
2. 스크립트는 항목마다 결과를 임시 로그 파일에 한 줄씩 남긴다(UTF-8). 사람에게 묻는 창을 띄우지 않는다.
3. `Start-Process -Verb RunAs -Wait` 로 **한 번** 실행한다. UAC 는 셋업 실행 1회에 최대 1회다.
4. 승격 창의 출력은 에이전트에게 보이지 않는다. 끝나면 일반 권한으로 같은 기준을 다시 확인해 항목마다 `바꿈`/`실패`를 정한다. 로그는 실패 이유를 적을 때만 쓴다. 예외: 승격 저장소 도구는 로그에 남은 `install.ps1` 출력 줄로 정한다([repo-tools.md](repo-tools.md)).
5. UAC 를 거부했거나 창이 뜨지 않았으면, 승격 단계에 넣은 항목을 모두 `실패: UAC 거부`로 기록한다. 그 항목에 의존하는 항목은 `실패: <앞 항목> 실패`로 기록하고, 나머지는 계속한다. UAC 를 다시 묻지 않는다.

### 5. 나머지 항목 맞춤

고정 항목 다음에, Windows 설정 → 앱 → 설정 파일 → 저장소 도구 순서로, 맞출 항목을 하나씩 처리한다.

1. 공식 문서에서 찾은 방법으로 맞춘다.
2. 같은 기준으로 **다시 확인**한다. 재확인은 빼먹지 않는다.
3. 통과하면 `바꿈`, 통과하지 못하면 `실패: <이유>`로 기록한다.

한 항목이 실패해도 다음 항목으로 넘어간다. 앞 항목에 의존하는 항목(예: scoop 설치가 실패했을 때의 scoop 앱 전부)은 시도하지 않고 `실패: <앞 항목> 실패`로 기록한다.

### 6. 끝 요약

대화의 마지막 메시지로만 남긴다. 파일로 남기지 않는다. 형식은 아래와 같다.

```text
셋업 끝
- 고정 항목: 그대로 1
- Windows 설정: 그대로 10 · 바꿈 1
- 앱: 그대로 44 · 바꿈 2 · 할 일 1
- 설정 파일: 그대로 3
- 저장소 도구: 그대로 1 · 할 일 1
할 일:
- <항목>: <할 일>
실패:
- <항목>: <이유>
```

- 개수가 0 인 결과 말은 적지 않는다. `할 일:`·`실패:` 목록이 비면 그 블록을 "할 일: 없음"·"실패: 없음" 한 줄로 쓴다.
- "계획과 다른 방법"으로 맞춘 항목이 있으면 `계획과 다른 방법:` 목록을 더한다.

## 셋업 밖의 일

셋업이 끝난 뒤 사람이 손으로 하는 일은 [README.md](README.md) 의 「손으로 할 일」에 있다. **에이전트 폴더**는 셋업이 건드리지 않는다.
