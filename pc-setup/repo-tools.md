# 저장소 도구 (repo-tools.md)

**셋업**이 설치하는 **저장소 도구**의 **선언**이다. 진행 방법은 [SETUP.md](SETUP.md) 를 따른다. 도구를 확인하고 설치하는 기준은 도구가 쥔다. 자세한 내용은 그 도구의 README 에 있다.

## 기본 규칙

- **셋업은 도구의 `install.ps1` 만 실행한다.** 레지스트리·작업 스케줄러·git config 를 직접 건드리지 않는다.
  - 확인: `pwsh -NoProfile -File <위치>/install.ps1 -Check` (읽기만 하므로 계획 승인 전에 실행해도 된다)
  - 맞춤: `pwsh -NoProfile -File <위치>/install.ps1`
  - `<위치>` 는 저장소 위치 칸의 경로를 저장소 폴더 기준 절대 경로로 바꾼 것이다.
- **출력 읽기**: 출력 한 줄을 다음처럼 읽는다.
  - `그대로` → `그대로`
  - `다름 (…)` → 계획의 맞출 항목
  - `바꿈` → `바꿈` (승격 단계 로그에서만 쓴다)
  - `할 일: …` → `할 일`
  - `실패: …` → `실패`
- **일반 권한 도구**(승격 칸이 비어 있음): 확인 단계에서 `-Check` 를 실행한다. 계획 승인 뒤 `install.ps1` 로 맞추고, 다시 `-Check` 를 실행해 그 출력으로 `바꿈`/`실패` 를 정한다(`그대로`가 나오면 `바꿈`).
- **승격 도구**(승격 칸이 `필요`): `-Check` 에도 관리자 권한이 필요하다. 그래서 일반 권한으로 확인하지 않고, 항상 **승격 단계**의 스크립트에 `install.ps1` 실행을 넣는다(멱등이라 상태가 맞으면 `그대로`를 출력한다). 그 출력 한 줄을 로그 파일에 남기고, 에이전트는 그 줄을 위 규칙대로 결과 말로 쓴다. `바꿈`은 로그의 줄이 `바꿈`일 때다.
  - 계획에는 승격 단계 목록에 "<도구>: 승격 안에서 확인하고 맞춤 (UAC 1회 필요)" 한 줄로 보여 준다. "확인 못 함" 줄과 구분한다.
  - 이 때문에 승격 도구가 선언에 있는 한, 셋업을 실행할 때마다 UAC 를 1회 묻는다.

## rdp-notify

- 설정 파일(env)이 없으면 `install.ps1` 이 `할 일: …` 을 출력한다. 그 줄을 그대로 끝 요약의 `할 일:` 에 옮긴다. env 파일은 사람이 만든다([../rdp-notify/README.md](../rdp-notify/README.md)).
