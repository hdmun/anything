## Git

- 커밋 메시지: Conventional Commits (`feat|fix|docs|chore|refactor|test(scope): 설명`). 설명은 한국어, `~한다` 체.
- 커밋 메시지는 ADHD가 있는 사람도 한눈에 이해하도록 쓴다. 제목은 "무엇이 어떻게 바뀌었는지"를 한 줄로 쓰고, 본문이 필요하면 짧은 불릿으로 나눈다. 모호한 표현·긴 문단·비유는 피한다.
- scope는 대상 패키지/디렉터리 이름 (예: `relay`).
- 브랜치: `hdmun/<주제>` 형식. 브랜치 작업은 그 주제의 작업 공간에서 하고, 머지는 루트 체크아웃에서 한다(아래 「작업 공간」).
- 커밋은 사용자 승인 없이 해도 된다. 푸시는 사용자가 요청할 때만 한다.
- 브랜치에 커밋이 2개 이상이면 `main` 기준으로 rebase한 뒤 non-ff 머지(`git merge --no-ff`)한다. 커밋이 1개면 `git merge --ff-only`로 머지한다.
- 한 커밋에는 한 가지 논리적 변경만 담는다.
- force push, `reset --hard` 등 되돌리기 어려운 명령은 사전 확인 후 실행한다.

### 작업 공간

여러 프로젝트의 세션이 이 저장소를 함께 쓴다. 루트 체크아웃은 플러그인 마켓플레이스의 원본이기도 하므로 늘 `main` 에 둔다. 용어(작업 공간·주제·루트 체크아웃·인계 메모)는 `GLOSSARY.md` 에 있다.

- 주제(브랜치 `hdmun/<주제>`)마다 작업 공간(워크트리) 하나를 만든다. 머지하거나 포기하면 그 작업 공간의 수명이 끝난다. 프로젝트마다 두는 상시 워크트리는 쓰지 않는다.
- 작업 공간 하나는 한 번에 세션 하나만 쓴다. 앞 세션이 끝난 뒤(아래 「앞 세션 확인」) 다른 세션이 이어받을 수 있다.
- 워크트리 이름은 `<주제>` 와 같다. 프로젝트 접두사는 붙이지 않아도 된다.
- 위치는 Orca 기본 경로 `~/orca/workspaces/scripts/<주제>` 하나다. 저장소 안의 `.claude/worktrees/` 에는 새 워크트리를 만들지 않는다.
- 작업 공간의 세션은 Orca 로만 띄운다. Orca 밖에서 사람이 직접 띄운 세션은 이 규칙이 보장하지 않는다.
- 다른 도구가 만든 워크트리에서 시작한 세션은 그 도구가 정한 작업 공간 규칙을 따른다.

### 루트 체크아웃에서 하는 일

- 허용: 읽기·조사, `git pull --ff-only`, 주제 브랜치를 `main` 에 머지, 머지한 `main` 푸시, 작업 공간 감독(기다리기·출력 읽기), 워크트리·로컬 브랜치 삭제, 이슈 트래커 작업(`gh issue`, 지도 갱신, 이슈 댓글).
- 그 밖의 일(파일 수정, 커밋, 브랜치 전환)은 작업 공간에서 한다. 오타 한 줄도 같다.
- 루트 체크아웃이 `main` 이 아니면 브랜치를 그대로 두고, 현재 브랜치를 사람에게 알린 뒤 머지·`pull` 을 멈춘다. 읽기는 계속해도 된다.
- 루트 체크아웃에 변경(추적 파일 수정·새 파일)이 남아 있으면 그 변경에 손대지 않는다(stash·삭제·커밋 모두). 사람에게 알리고 머지·`pull` 을 멈춘다. `.gitignore` 에 걸린 항목은 변경으로 보지 않는다.

### 루트에서 일을 넘기기

루트에서 시작한 세션은 허용된 일 밖의 첫 작업(파일 수정·커밋·브랜치 생성) 직전에 일을 작업 공간으로 넘긴다. 세션이 스스로 워크트리로 옮겨 가지 않는다.

1. `git fetch origin` 뒤 `orca worktree create --repo path:<저장소> --name <주제> --branch hdmun/<주제> --base-branch origin/main --no-parent` 로 워크트리를 만든다. `git worktree add` 는 쓰지 않는다. 같은 주제의 워크트리가 이미 있으면 새로 만들지 않고 그 워크트리를 쓴다. 커밋하지 않은 변경이 남아 있으면 인계 메모에 적는다.
2. 앞 세션이 살아 있는지 확인한다(아래 「앞 세션 확인」).
3. 그 워크트리에 새 에이전트를 띄우고 인계 메모를 넘긴다. 에이전트 종류는 사람이 따로 지정하지 않으면 루트 세션과 같은 종류(Claude Code·Codex·Antigravity)다.
4. 루트 세션은 감독 세션으로 남는다(아래 「감독·머지·삭제」).

- 인계 메모에는 주제 이름, 목표, 목적·의도, 루트에서 확인한 사실, 끝 조건을 적는다. 끝 조건에는 항상 "`origin/main` 위로 rebase 완료와 결과 보고"를 넣는다.
- `orca` 를 못 쓰는 세션(샌드박스를 켠 Codex 등)은 루트에서 수정하지 않는다. 사람에게 워크트리 생성과 세션 기동을 짧은 명령 하나로 요청하고 멈춘다.

### 앞 세션 확인

- 워크트리에 새 에이전트를 띄우는 세션은 띄우기 직전에 확인한다. 사람이 직접 이어받게 한 세션은 일을 시작하기 전에 스스로 확인한다.
- `orca terminal list --worktree path:<워크트리 경로> --json` 에 `agentIdentity` 가 붙은 터미널이 하나라도 있으면 앞 세션이 살아 있다고 본다. `agentIdentity` 가 없는 일반 셸 터미널은 세지 않는다.
- 일을 마치고 프롬프트에 머문(`tui-idle`) 에이전트도 터미널이 열려 있으면 살아 있다. 다른 세션이 이어받게 하려면 사람이 그 터미널을 닫는다.
- 살아 있으면 새 에이전트를 띄우지 않고, 그 터미널을 닫거나 입력을 보내지도 않는다. 사람에게 터미널 핸들과 마지막 출력을 알린 뒤 멈춘다.
- 예외: 감독 세션은 자기가 띄운 에이전트에게 `orca terminal send` 로 일을 다시 맡길 수 있다.

### 감독·머지·삭제

- 감독 세션은 `orca terminal wait --for tui-idle` 로 작업 공간 세션이 끝나기를 기다린다. 그 뒤 터미널 출력과 `git log main..hdmun/<주제>` 를 확인하고, 사람에게 보고하며 머지할지 묻는다.
- 작업 공간 세션은 자기 워크트리에서 `origin/main` 위로 rebase 하고 충돌을 해결한 뒤 보고하고 끝난다. 브랜치는 로컬에만 두고 PR 도 열지 않는다.
- 사람이 한 번 승인하면 감독 세션이 아래를 연달아 진행한다. 이 승인을 "푸시는 사용자가 요청할 때만" 규칙의 요청으로 본다.
  1. 머지 직전 검사: `git pull --ff-only` → `git status` 가 깨끗하고 진행 중인 머지가 없음 → `git merge-base --is-ancestor main hdmun/<주제>` 성공.
  2. 머지: 커밋이 2개 이상이면 `git merge --no-ff`, 1개면 `git merge --ff-only`.
  3. `git push origin main`
  4. `git -C <워크트리 경로> status` 가 깨끗한지 확인한 뒤 `orca worktree rm --worktree path:<워크트리 경로> --delete-branch`.
- `is-ancestor` 검사가 실패하면(`main` 이 앞섰으면) 머지하지 않는다. 같은 워크트리에 rebase 를 다시 맡기고(「앞 세션 확인」을 따른다), 보고를 받은 뒤 검사를 처음부터 다시 한다. 충돌은 작업 공간에서만 해결한다.
- 아래 경우에는 그 자리에서 사람에게 알리고 멈춘다. 상태는 그대로 둔다.
  - git 잠금(`index.lock`)·진행 중인 머지로 명령이 실패했다: 잠금 파일을 지우거나 `--abort` 를 실행하지 않는다.
  - `git push origin main` 이 non-fast-forward 로 거부됐다: force push 하지 않는다.
  - 지울 워크트리에 변경이 남아 있다: `--force` 로 지우지 않는다.
- 감독 세션끼리 쓰는 잠금 파일이나 순서 규칙은 만들지 않는다.
- 포기: 사람이 "포기"라고 말한 경우에만 포기로 본다. 그 말을 들은 세션이 워크트리를 지운다. 머지되지 않은 로컬 브랜치는 사람이 다시 확인한 뒤 `git branch -D hdmun/<주제>` 로 지운다.
